## general
what am i expecting to learn in this module?
-  how to design a software before coding it
-  organise and plan implementation
-  making a prototype of the project that runs, doesn't have to be market ready but has to work
-  using UML diagrams to think through and describe designs

this module lives in the analysis and design phase of the software development cycle
**analysis = problem space - what the system does
design = solution space - how the system does it**

**software architect** - allows you to explain the idea from the customer, how it should be on the paper, and how it should be implemented (not actually software developers, more like managers that don't necessarily have the technical knowledge)
**software developer** - implements a particular plan or fixes the existing software

**agile software development** - dividing the implementation into sprints that span through multiple weeks, one sprint each week

how would you describe a new website to someone that doesn't know how it looks like?
-  you describe the layout and components to the customer
-  you have a team, you explain how to develop the website to them by making a list of requirements, use the point of view of both the admin and the customer

## class vs object

class - common blueprint
object - instances based off the blueprint

## why is design important?

-  fixing mistakes in production phase or after is very expensive (millions of euros), but it is free in the design phase
-  const of change exponentially growns with each phase

## why do software projects fail?

-  requirements and communication problems
-  incorrect context

## object oriented thinking

procedural thinking - data and functions are considered to be separate
object oriented thinking - considering behaviour when two are bundeled together

## UML

-  a design language
-  needed for modelling of the software before the implementation
-  this is how we see what the system will look like
-  helpful for all stakeholders involved with the project
-  we will focus on class, object, component and deployment for **structural diagrams**
-  use case, activity, state machine, sequence and communication diagrams for **behavioural diagram**
